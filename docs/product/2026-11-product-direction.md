# 产品方向复盘与建议（2026-11）

> 背景当前提：站点的唯一付费点是生词本 TSV(Anki) 导出（Ed25519 license 校验），
> 上线以来零成交。本文回答三个问题：为什么没人买？这个产品真正的付费价值在哪？
> 下一步按什么顺序做？——小步可落地的部分已随本文一起提交，大动作在文末路线图。

## 一、为什么 TSV 导出没人买

按重要性排序，前三条几乎是致命的：

1. **根本没有「购买」这个动作。** 付费面板是一个冷输入框：「粘贴 License」。
   没有价格、没有购买链接、没有说明。License 由管理员用 CLI 私下签发——
   也就是说，一个对产品一无所知的访客即使想买，也不知道去哪付钱。
   （本轮已修：面板加了「解锁后你会得到 / 如何获得」上下文，指向项目主页。）
2. **墙的位置错了：它守在价值闭环的末尾，而不是价值的源头。** TSV 导出发生在
   「读完书、攒了生词」之后——一个新用户要先用满几周才走到墙前，而走到墙前的
   重度用户恰恰是最有能力自己写脚本转 JSON→TSV 的人。免费 JSON 导出就摆在旁边，
   进一步吸干了差异价值。
3. **付双份钱的心理账户冲突。** 这是 BYOK 产品：AI 释义的钱用户已经直接付给
   模型商了。再为「导出自己产生的数据」付一次钱，感知是重复收费。
   用户不反感为「省事/额度/一致性」付费，反感为「我的数据出口」付费。

次要原因：Anki 导入是强需求但小众人群；对大多数语言学习者，「读得下去」
本身比「复习卡片」更痛——付费点应该贴着最痛的地方。

## 二、这个产品的付费价值到底在哪

先把「谁在用、为什么留下」说清楚。逐词对照阅读器的核心体验是：

> **不开小差、不切词典 App，把原版书读完。** 词典免费标注解决 80% 的词，
> AI 补语境义解决剩下 20%，生词本承接「读完之后」的积累感。

由此，用户真正愿意付钱的三类价值（按强度排序）：

| 价值                                  | 为什么愿意付                                               | 现状                                     |
| ------------------------------------- | ---------------------------------------------------------- | ---------------------------------------- |
| **AI 释义额度（代付 key）**           | 「不想搞 API key」是 BYOK 的天然流失点；提供额度 = 卖便利  | 无：必须自备 key，注册/充值/限额全靠自己 |
| **整书 AI 一致性（术语表/专名统一）** | 一次性重活（整本书过一遍上下文窗口），我们自己承担算力编排 | 已有 extractBookGlossary，但走用户的 key |
| **跨设备/跨会话的书架与进度**         | 数据资产感：书、进度、生词本跟着走                         | 无：书在内存里，刷新即丢，每次都要重传   |

对应的产品主张（对外一句话）：

> **「像读中文书一样读英文原版书。」** 免费把 7 种语言的词典注释送到底，
> 付费解锁「AI 额度 + 整书一致性 + 云端书架」——墙设在体验升级处，不在数据出口处。

## 三、免费/付费边界怎么划（推荐口径）

- **免费（获客面，越宽越好）**：词典逐词注释（7 语言、不限量）、富文本排版、
  生词本、JSON 导出、演示书。这一层必须「不用注册、不填 key、30 秒见效」。
- **付费（价值升级面）**：
  - P0「AI 静读额度」：按月额度代替 BYOK（如 ¥19/月 50 万 token 概念额度），
    我们在服务端持 key、按额度计费。BYOK 保留为「极客模式」永久免费。
  - P1「整书一致性」：一次购买/按本收费，服务端跑整书术语表 + 逐章注出缓存。
  - P2「云书架」：书 + 进度 + 生词本同步（需要账号体系）。
- **明确不卖**：数据导出（TSV/JSON 全部免费）。把 Anki 导出改成免费，
  并在文档里写明——它是留存工具，不是收入工具。现有 license 体系可保留
  给未来的「一次性买断」场景（如终身会员），不必删除。

> 关键提醒：P0 需要服务端（Worker + key 托管 + 计费），与当前
> 「static-only、无 Worker、无 DB」的架构前提冲突，是架构级决定，
> 需要你拍板后再动工。在此之前，先用 BYOK 免费换取增长，
> 不建议再在无后端的前提下发明新的收费点。

## 四、转化面检查清单（本轮已落地的 ✅）

- ✅ **首屏价值主张**：书架顶部加 Hero（标题/三步用法/免费口径/隐私口径），
  新访客第一屏不再是冷的文件表单。
- ✅ **演示书升级**：启动示例从玩具句换成有情节的小故事
  （The Cat in the Garden），全部词过真实词典链验证（segment+lemmatize 全命中），
  不填 key 就能看到完整效果。
- ✅ **付费面板上下文**：TSV 面板补「解锁后你会得到/如何获得」。
- ✅ **可诊断的部署**：构建指纹显示在设置→关于，`npm run check:deploy`
  一键比对线上与本地产物（2026-11 事故：线上部署落后数月，用户看到的
  bug 源码早已修复——转化优化的前提是「线上就是最新版」）。
- ⬜ **30 秒演示路径**（下一个最划算的小改动）：进站自动滚动到阅读页 +
  高亮第一个可点词的引导气泡（「点我看看释义」），把「这能干嘛」变成动作。
- ⬜ **首屏示例更多语言**：演示书目前只有英文；加一章 ja/de 各一段，
  让不同母题的访客都能看到自己语言的效果。
- ⬜ **移动端首屏**：目前 Hero 与表单在窄屏的堆叠顺序未经真机验证，
  上线前用真机过一遍（阅读页本身有响应式，但书架没有）。

## 五、路线图（建议优先级）

**P0（1-2 周，纯前端）**

1. 30 秒演示路径（引导气泡 + 自动聚焦可点词）。
2. 书架持久化：IndexedDB 存最近一本书 + 阅读位置，刷新/重开浏览器后
   「继续阅读《X》第 N 章」。留存的最大单点，纯前端可做（Blob 可直接入 IndexedDB）。
3. 生词本闭环小步：生词数角标（导航栏）、今日新增统计。

**P1（需要拍板/后端）** 4. AI 额度付费（Worker 托管 key + 额度计费 + 客户端额度核销）。
这是把「有消费欲望」变成「有消费动作」的那一步。5. 整书一致性作为 P4 的附属卖点（同一套额度体系内按本计费）。

**P2（增长面）** 6. 落地页独立于应用（营销页 + demo iframe），SEO 关键词：
「EPUB 逐词对照 / interlinear reader / 英文原版书 逐词翻译」。7. 用户案例与真实截图（读一本书第 50 页时的效果，比第一页更有说服力）。
